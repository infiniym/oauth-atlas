## Changes

### Steps developers can actually follow

- Instructions and verification tasks remain visible beside their step without disabling it. Only unmet prerequisites and missing specifications block progress.
- Missing resource-request evidence blocks that resource test, not authorization. Genuine prerequisites still propagate to dependent steps.
- One representative action test is retained per requested action. Existing steps are augmented, duplicate placeholder references are redirected, and obsolete endpoint gaps are removed after a documented request passes access review.
- Prior snapshots are immutable. A saved guide with obsolete blocker behavior offers **Apply guide fixes**, creating a new version without another research or model call.

### Resolve one missing item

**Find missing request** and **Add documentation** use the existing request, answers and saved evidence. They fetch a bounded set of pages and use a small structured model response for one action. The server owns action identity, step identity and dependencies. New instructions still pass source, endpoint, permission and independent access checks.

Unrelated actions and their uncertainties remain intact. An unresolved placeholder elsewhere cannot invalidate the selected action's update. Missing evidence remains explicit when discovery cannot find it. Failed updates preserve the prior guide and save newly collected sources for retry.

**Record my check** saves a dated developer report. A developer can report satisfying an explicit prerequisite, but cannot use a checkmark to establish missing permission documentation. Product execution remains `setupTested: false`; checkmarks and user reports do not imply that OAuth or an API test ran.

### Completion and failure

Final planning uses a smaller response contract, with local defaults for repeated summaries and empty fields. Haiku retains adaptive thinking at medium effort. The independent access review has a bounded 35-second budget and a 6K output cap, allowing room for thinking.

An additional defect was found during live testing: context compression discarded short, non-citable lines. This hid the actual GraphQL endpoint even though it existed in the saved source. URLs and code syntax now remain model context, explicitly marked as non-citable when appropriate. Quotations still must match an eligible saved passage.

Failed jobs no longer emit “Guide ready” or save fallback findings as a completed plan. The failure screen states that the guide/update could not finish, shows saved source count, exposes the sources, and offers retry of the same job. It does not render a contradictory plan underneath. Running-job reload restores the original request from job input. Identity and permission labels use developer-facing language.
