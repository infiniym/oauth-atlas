# Unified-plan evaluation — 31 October 2026

This evaluates the combined local checkout. It supersedes the earlier architectural split between reviewed-provider results and a separately styled Live Guide. It does not claim a refreshed hosted deployment or completed provider setup.

## Implementation examined

- One `LaunchPlan` contract, application shell and renderer for Gmail, Slack, GitHub, unfamiliar-provider research and clearly labeled reference scenarios.
- Consistent next action, owner, preparation fields, completion criterion, hands-on effort, provider wait, permission map, first test, conditional launch steps, consequence-labeled blockers, preparation drafts and sources.
- One shared Anthropic model selection for intake and research. Haiku 5.5 adaptive thinking at medium effort is enabled in both. Legacy research-only bindings are compatibility aliases; explicit disablement wins.
- Unfamiliar-provider research does not depend on catalog membership. It ranks setup topics and requested API actions, with one bounded follow-up, source snapshots, exact scope preservation and deferred-question carryover.
- Reviewed shares save computed output and inputs. Research versions remain immutable. Both open under `/plan/:id`; legacy live-guide links remain compatible. Local checkmarks are independent.

## Failures that informed the change

1. Initial Notion interpretation exceeded its repair budget. The mechanical fallback found an OAuth limitation for a different Notion product and applied it too broadly. Fallback now preserves that limitation as local evidence while leaving overall support unknown.
2. Context compression dropped Linear's exact `comments:create` entry while retaining a broad permission description. Short permission entries now survive, with a regression case. Follow-up results selected the narrower permission.
3. Generic permissions research stopped at scope lists, leaving Asana's endpoint mapping unresolved. Requested API resources now influence candidate ranking; read-only requests penalize mutation endpoints. A scope/capability topic still takes priority over unrelated API references.
4. Redirect aliases were counted as new follow-up documents. Final URLs now deduplicate against saved sources; older evaluated records preserve their historical duplicates.
5. Shared intake initially fell back in under a second: the live Anthropic API rejected a nullable enum schema that controlled-response tests had accepted. The schema now uses explicit alternatives and the real intake returned AI suggestions. Anthropic requests use the API-key header.
6. One development Asana run took about 224 seconds with a failed follow-up. Its earlier valid plan survived but timing telemetry omitted the failed follow-up. Telemetry now totals both rounds and records the follow-up outcome. The bounded result remains provisional when material evidence is unresolved.

The final read-only ranking and source-deduplication refinements have automated coverage; not every real provider sample above was rerun after each final refinement. This is a small evolving evaluation set, not a universal provider benchmark.
